# 設計書：kirinuki-pipeline

作成：2026-10-25（Claudeとの会話から）

## 1. 目的

加藤純一さんのTwitch配信から、次の3種類の動画を自動で作る。

| 種類 | 長さ | 画角 | 作り方 | 目標本数 |
|---|---|---|---|---|
| ショート | 15〜60秒 | 縦 9:16 | 1つの山場をそのまま | 1配信 2本まで（面白さ8以上。1日2本まで、長い動画の枠とは別に数える。2026-11-03 再開） |
| 最新速報 | 10〜60分 | 横 16:9 | その配信の山場を時系列でつなぐ、チャプター付き。ショートとは別の場面が中心 | 1配信 1〜3本（材料の量に応じて。ゲーム・時間帯ごと） |
| 総集編 | 30分〜 | 横 16:9 | 企画・ゲームシリーズ単位で複数配信を横断 | 半手動（フェーズ6） |

- 発言の字幕なし。視聴者コメントはニコニコ風に右から左へ流す（3.7.1）。
- 速報は**配信終了から数時間以内**に下書きがそろっていることが勝負。
- 名前は既存の公認チャンネル（「加藤純一ロードショー」など）と被らないものにする。
- チャンネル名：**加藤純一 最速切り抜き**（非公式。概要欄に「非公式の切り抜きチャンネルです」と明記する）

## 2. 全体の流れ

```
[GitHub Actions: 定期実行 or 手動]
   │
   ├─ 1. 新着検知     Twitch Helix API（アーカイブ一覧・配信中か）
   ├─ 2. チャット取得   TwitchDownloaderCLI → chat.json（数MB）
   ├─ 3. 山場検出     チャット流速＋反応語 → 候補20件
   ├─ 4. 区間DL       yt-dlp --download-sections（候補区間のみ）
   ├─ 5. 文字起こし    faster-whisper（候補区間のみ）
   ├─ 6. 選定・命名    Claude API → 採用/不採用・開始終了の微調整・タイトル・説明
   ├─ 7. 書き出し     ffmpeg → shorts/*.mp4, digest.mp4, thumbs/*.jpg
   ├─ 8. 保存       rclone → Googleドライブ kirinuki/<日付>_<VOD_ID>/
   ├─ 9. 非公開アップ   YouTube Data API（private）
   └─ 10. 状態更新    state/processed.json をコミット
           │
           ▼
[オーナー] iPhoneのYouTube Studioで確認 → 公開ボタン
```

## 3. 各ステップの仕様

### 3.1 新着検知（`twitch.py`）

- Client Credentials でアプリトークンを取得。
- `GET /helix/users?login=kato_junichi0817` → user_id（初回のみ、configにキャッシュ）。
- `GET /helix/streams?user_id=...` が空でなければ**配信中なので何もしない**（配信中のアーカイブは未完成）。
- `GET /helix/videos?user_id=...&type=archive&first=5` から、`state/processed.json` に無いVODを処理対象にする。
- `created_at + duration` が現在時刻の5分以上前であることを確認する（配信終了直後の確定待ち。2026-10-28に10分から短縮）。
- 終了から `auto.max_age_hours`（初期値48時間）を過ぎたVODは自動では処理しない（初回起動時に過去のアーカイブをまとめて上げないため）。1回の実行で `auto.max_vods_per_run`（初期値2本）まで、**新しい配信から**処理する。
- **即時検知（フェーズ4の改善）**：Twitch EventSub の `stream.offline` を Cloudflare Workers（`worker/notify.js`）で受け、署名（`TWITCH_EVENTSUB_SECRET`）を検証してから、GitHub の `repository_dispatch`（`stream_offline`）を送る。GitHubへの合図には、このリポジトリだけに限った権限（Contents: 書き込み）のトークンを使い、Cloudflareのシークレットにだけ保存する。
- 合図を受けたワークフローは5分待ってから自動検知モードで処理する（アーカイブの確定待ち）。
- 定期実行は、通知を取りこぼしたときの保険として6時間おきに減らす。
- サブスク限定アーカイブで取得に失敗した場合は、エラーにせず `state` に `skipped_auth` と記録して次へ。必要になったら `TWITCH_AUTH_TOKEN`（オーナー本人アカウント）を任意で使えるようにする。

### 3.2 チャット取得（`chat.py`）

- `TwitchDownloaderCLI chatdownload --id <VOD_ID> -o work/<id>/chat.json --compression None`
- 使う項目：`comments[].content_offset_seconds`、`comments[].message.body`、`comments[].message.fragments[].emoticon`。
- 失敗時のフォールバック：Python の `chat-downloader` パッケージ。

### 3.3 山場検出（`peaks.py`）— 純粋関数で書き、単体テスト必須

1. 5秒ごとのビンにメッセージを集計する。1メッセージ1点に加えて、反応語に加点する。
   - 笑い：`草` `ｗｗ` `www` `笑` → +0.5
   - 驚き・盛り上がり：`！？` `!?` `ファ` `うおお` `ええ` `神` → +0.5
   - 同一文の連投（弾幕）：同じビン内で同一本文が3件以上 → その本文の件数×0.3
   - 反応語・重みは `config/channel.yaml` で調整可能にする。
2. 3ビンの移動平均で平滑化。
3. 直前10分の中央値とMAD（中央絶対偏差）でロバストZスコア化。
4. Z ≥ `peak_threshold`（初期値 2.5）の極大を山場とし、60秒以内の山場は統合。
5. チャットは出来事から5〜15秒遅れて反応するため、候補区間を `[山場 − 45秒, 山場 + 15秒]` とする（`lead_sec` `tail_sec` で調整）。
6. スコア上位 `max_candidates`（初期値 80）件を候補として返す。各候補は `{id, peak_sec, start_sec, end_sec, score, top_messages[10]}`。

### 3.4 区間ダウンロード（`fetch.py`）

```bash
yt-dlp "https://www.twitch.tv/videos/<VOD_ID>" \
  -f "best[height<=1080]" \
  --download-sections "*<start>-<end>" \
  -o "work/<id>/seg_<cand_id>.%(ext)s"
```

- まず候補20件すべてについて、**音声だけ**（`-f audio_only`）を山場の `context_lead_sec` 前〜`context_tail_sec` 後の範囲で取得し、山場の瞬間の静止画を1枚（480p程度）取得する。
- Claudeが採用した区間だけ、1080pの映像を取得する（余白付き）。
- 速報用は同じ区間を使い回す（再ダウンロードしない）。

### 3.5 文字起こし（`transcribe.py`）

- faster-whisper `base`、`compute_type=int8`、CPU、`language="ja"`、`beam_size=1`（速さ優先。2026-10-28に small から変更）。
- モデルは `actions/cache` でキャッシュ。
- 精度不足なら `medium` に上げるか、設定で外部API（OpenAI Whisper等）に切り替えられるようにする。
- 字幕には使わない。Claudeが中身を理解して選定・命名するための材料。

### 3.6 選定・命名（`select.py` + `prompts/select_clips.md`）

- モデル：`claude-sonnet-5-5`（`config/channel.yaml` で変更可）。
- 入力：候補ごとの文字起こし（タイムスタンプ付き）、上位チャット10件、スコア、配信タイトル・ゲーム名。
- 出力（JSONで受け取り、スキーマ検証する）：

```json
{
  "clips": [
    {
      "cand_id": 3,
      "keep": true,
      "reason": "採否の理由を1文で",
      "kind": "short | digest | both",
      "in_sec": 3721.5,
      "out_sec": 3768.0,
      "short_in_sec": 3730.0,
      "short_out_sec": 3768.0,
      "title": "40字以内",
      "band": ["1行目（赤）", "2行目（白）"],
      "thumb_text": "サムネ用の短い言葉",
      "thumb_sec": 9670.0,
      "crop": {"mode": "both | game | face", "cx": 0.5, "cy": 0.5, "size": 1.0, "fx": 0.88, "fy": 0.75, "fsize": 0.35},
      "hook": "なぜ面白いかを1文で",
      "quality": 8
    }
  ],
  "digests": [{
    "title": "速報のタイトル",
    "order": [3, 7, 12],
    "chapters": [{"cand_id": 3, "label": "チャプター名"}],
    "description": "概要欄の本文（元配信URLと時刻はコード側で付ける）",
    "thumb_text": "速報サムネの言葉"
  }]
}
```

- 入力に、候補ごとの山場の静止画を1枚加える（拡大する場所を決めるため）。
- `in_sec`/`out_sec` は場面全体（速報で使う。最大120秒程度）、`short_in_sec`/`short_out_sec` はショート用（60秒以内、場面の中）。
- `digests` は1〜3本。同じ場面を複数の速報に入れない。ショートにした場面は速報1本につき `digest_max_short_scenes`（2）つまで（コード側でも検証する）。
- `band` は各行全角10字以内（半角は2文字で1字）。`crop` は元映像に対する正方形の切り抜きで、中心（cx, cy）と大きさ（size＝映像の高さに対する比率）を0〜1で表す。`both` のときは、小窓のカメラ部分を `fx`・`fy`・`fsize` で同様に表す。
- `mode` の使い分け：迷ったら `both`。`face`（カメラだけ）は、ゲーム画面がなくても分かる雑談・リアクションの場面に限る。
- 呼び出しは1配信1回。使ったトークン数をログに出す。
- ルール（プロンプトに明記）：オチまで入れる、話の途中で切らない、ショートは60秒以内、似た場面ばかり選ばない、タイトルは釣りすぎない、身内ネタは文脈が分かる場面を優先する。

### 3.7 書き出し（`render.py`）

**ショート（1080×1920）**：
- 上（0〜440）：黒帯。`band` の2行を極太で（1行目は赤、2行目は白）。
- 中（440〜1520）：Claudeの `crop` で元映像を正方形に切り抜き、1080×1080で表示する。`both` のときは、右下に加藤さんのカメラの小窓（360×360、白枠）を重ねる。流れるコメントはここに流す（小窓の上までの範囲）。
- 下（1520〜1920）：元映像を拡大してぼかした背景（YouTubeのボタン・チャンネル名が重なる場所なので、情報は置かない）。
- フォントは Noto Sans CJK JP の Black（Actionsでは `fonts-noto-cjk-extra` を入れる）。文字は ffmpeg の `ass` フィルタで焼き込む。

```
[0:v]scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920,boxblur=20:5[bg];
[0:v]scale=1080:-2[fg];
[bg][fg]overlay=(W-w)/2:(H-h)/2
```

- 音声：`loudnorm=I=-14:TP=-1.5:LRA=11`。
- エンコード：`libx264 -preset veryfast -crf 20`、`aac 160k`。速報は容量と時間を抑えるため30fps・`-crf 24`・`-preset superfast`（YouTube側で再圧縮されるので見た目の差は小さい）。
- 発言の字幕は入れない。流れるコメントは3.7.1。

**速報（1920×1080）**：元映像をそのまま使い、流れるコメント（3.7.1、画面の上3/4）を焼き込む。Claudeの `order` 順に区間をつなぐ。区間の境目は音声0.3秒フェード。チャプターは区間の長さから計算し、`00:00 チャプター名` 形式で概要欄に入れる（最初のチャプターは必ず00:00、各10秒以上＝YouTubeの要件。10秒未満の区間は前のチャプターにまとめる）。速報サムネは1280×720で、`digest.thumb_text` を大きく載せる。

**サムネ（フェーズ2で作成、YouTubeへの設定はフェーズ5）**：Claudeが選んだ `thumb_sec`（区間外なら山場の時刻）のフレームを抜き、`thumb_text` を極太の文字で大きく載せる（ffmpeg＋ASS。Pillowは使わない）。文字はワイプに重ならない位置に置く。ドライブの `thumbs/` に保存する。

### 3.7.1 流れるコメント（`comments.py`）

- 材料：チャット取得（3.2）の `chat.json`。追加ダウンロードなし。
- 各コメントは元配信と同じ時刻（`content_offset_seconds − 区間開始秒`）に出し、右から左へ `duration_sec`（初期値4秒）かけて流す。
- 除外するもの：
  - NGワード（`config/ng_words.txt`。全角・半角などの表記ゆれをそろえてから部分一致で判定）。差別語・性的表現・暴力や脅迫・個人情報らしき文字列。
  - スタンプ（エモート）だけのコメント。メッセージ内のスタンプ部分は取り除いて、残りの文字だけ流す。
  - URLを含むコメント、`@` で始まる返信。
  - `max_chars` を超える長文。
- 表示：白文字＋黒フチ、太字の日本語フォント（Actionsでは `fonts-noto-cjk` を入れる）。流す段（レーン）をいくつか用意し、重ならないように空いている段へ割り当てる。空きが無いコメントは捨てる（画面が埋まるのを防ぐ）。
- 範囲：ショートは中央の元映像の帯の中、速報は画面の上から3/4まで。右下の配信者のカメラ映像にはなるべくかぶせない。
- 作り方：ASS形式の字幕ファイルを生成し、ffmpegの `ass` フィルタで焼き込む。
- NGワードと段の割り当ては純粋関数で書き、フィクスチャで単体テストする（`tests/test_comments.py`）。

### 3.8 保存（`publish_drive.py`）

- `rclone copy work/<id>/out gdrive:kirinuki/<YYYY-MM-DD>_<VOD_ID>/`
- 中身：`shorts/*.mp4`、`digest.mp4`、`thumbs/*.jpg`、`candidates.md`（候補一覧・スコア・採否・タイトル・元配信の時刻リンク）、`metadata.json`。
- `candidates.md` はiPhoneで読んで採否を判断できる形にする。
- `upload.md`：ショートと速報それぞれの、YouTube用タイトル・概要欄（元配信のリンクと時刻、チャプター、ハッシュタグ）。手動アップロード時はこれをコピーする。
- **自動お掃除**：各実行の最後に、`gdrive:kirinuki/` 内で作成から `drive.retention_days`（初期値7日。1配信で約1GBになるため）を過ぎたファイルを削除し、空になったフォルダも消す（`rclone delete --min-age 7d --drive-use-trash=false` ＋ `rclone rmdirs --leave-root`）。
  - ゴミ箱に入れても容量を使うため、ゴミ箱を経由せずに完全に削除する。
  - `drive.file` 権限なので、このツールが作ったファイル以外には触れない。

### 3.9 YouTube 非公開アップ（`publish_youtube.py`、フェーズ5）

- `videos.insert`、`privacyStatus` は `youtube.privacy`（2026-10-28から `public`。`private` に戻せる）、カテゴリ20（ゲーム）、`defaultLanguage=ja`。
- 概要欄：Claudeの説明文＋`元配信：<URL>?t=<h>h<m>m<s>s`＋チャプター（速報のみ）。
- **クォータ**：2026-06-01以降、`videos.insert` は専用の枠で1回1ユニット、1日100回まで（[公式](https://developers.google.com/youtube/v3/docs/videos/insert)、2026-10-26確認）。旧記述の「1本1,600ユニット・1日6本」は古い。`daily_upload_limit`（今は4） は、量産に見えないための**自主的な上限**として残す。
- **チャンネルごとの1日の上限**：YouTube側にも本数の上限があり（`uploadLimitExceeded`。本数は非公開、新しいチャンネルほど少ない）、2026-10-27に24時間で10本上げたところで止まった。上限に当たったらその回のアップロードを止め、上げられなかったファイルを `state/processed.json` の `youtube_pending` に残す。次の自動処理の最後に、ドライブの `upload.md` とファイルを取り寄せて上げ直す。
- **審査前のアプリからのアップロード**：2026-10-27に1本上げて確認し、Studioで公開に切り替えられた（ロックされない）。
- 認証：`kirinuki` プロジェクトのOAuthクライアント（デスクトップ）を使い回し、スコープは `youtube.upload` のみ。リフレッシュトークンは `python -m kirinuki auth youtube` で取得し、画面に出さずに `gh secret set` で登録する（YOUTUBE_CLIENT_ID / YOUTUBE_CLIENT_SECRET / YOUTUBE_REFRESH_TOKEN）。
- 実装：Googleの重いライブラリは使わず、REST（resumable upload）を直接呼ぶ。
- タイトル：`title` ＋ `youtube.title_suffix`（初期値「【加藤純一】」）。概要欄：元配信（タイトル・日付・時刻付きリンク）＋チャンネル紹介1行＋ハッシュタグ。サムネは `thumbnails.set` で設定し、失敗しても動画は残す。
- 手動実行では、入力 `youtube: true` のときだけアップロードする（同じVODのやり直しで二重に上げないため）。定期実行（自動検知）では、`state/processed.json` に無い新しいVODだけを処理して常にアップロードする。1回の実行で `daily_upload_limit` 本まで。
- アップロード結果（動画ID・URL）は `metadata.json` と `upload.md` に記録する。

### 3.10 状態管理（`state.py`）

- `state/processed.json`：`{vod_id: {status: done|skipped_auth|failed, processed_at, clips: [...], youtube_ids: [...]}}`
- ワークフローの最後に `github-actions[bot]` としてコミット＆プッシュ。
- `failed` は3回まで自動リトライ、それ以上は止めてログに理由を残す。

## 4. GitHub Actions（`.github/workflows/run.yml`）

- トリガー：
  - `workflow_dispatch`（入力 `vod_id` 任意。空なら自動検知モード）
  - `repository_dispatch`（`stream_offline`）：配信終了の通知で即時に起動
  - `schedule`：`17 */6 * * *`（6時間おき。保険）
- `concurrency: { group: kirinuki, cancel-in-progress: false }`（二重実行防止）
- `timeout-minutes: 300`、`permissions: contents: write`
- 手順：checkout → setup-python 3.12（pipキャッシュ）→ `apt-get install ffmpeg` → TwitchDownloaderCLI（linux-x64）をリリースから取得 → whisperモデルのキャッシュ復元 → `python -m kirinuki run` → state をコミット。
- `work/` は処理後に削除。

### 実行時間の予算

- 非公開リポジトリの無料枠は月2,000分。
- 何も無いときの定期チェックは1回1分前後 × 1日12回 × 30日 ≒ 360分。
- 1配信の処理は30〜60分の見込み。ほぼ毎日配信なら月900〜1,800分。
- → 合計で無料枠ぎりぎり。超過分は従量課金（少額）。GitHubの支払い上限（spending limit）を設定しておく。
- 将来の最適化（フェーズ4以降）：Twitch EventSub の `stream.offline` を Cloudflare Workers（無料）で受けて `repository_dispatch` を叩けば、定期チェックが不要になり速報も早くなる。

## 5. 設定ファイル（`config/channel.yaml`）

```yaml
channel_login: kato_junichi0817
model: claude-sonnet-5-5
peaks:
  bin_sec: 5
  smooth_bins: 3
  baseline_window_sec: 600
  peak_threshold: 2.5        # 長いまとめ動画（〜1時間）の材料を集めるため緩めた
  merge_within_sec: 60
  lead_sec: 45
  tail_sec: 15
  context_lead_sec: 60     # 文字起こし・速報用に取る範囲（山場の60秒前〜15秒後）
  context_tail_sec: 15
  max_candidates: 80
  reaction_words:
    laugh: ["草", "ｗｗ", "www", "笑"]
    hype: ["！？", "!?", "ファ", "うおお", "ええ", "神"]
  bonus: { laugh: 0.5, hype: 0.5, spam_per_msg: 0.3, spam_min_count: 3 }
output:
  shorts_per_vod: 2            # ショートは1配信2本まで（2026-11-03 オーナー判断で再開：前のショートは1本1,200〜1,900回と長い動画より見られている。新しく見てくれる人の入口にする）
  shorts_min: 0
  short_min_quality: 8          # 面白さ8以上のときだけショートを作る
  transcribe_top: 30           # 盛り上がり上位30件だけ文字起こし（残りはチャットと画面だけでClaudeに渡す）
  short_max_sec: 60
  digest_min_sec: 480          # 途中の広告（ミッドロール）は8分以上の動画から
  digest_max_sec: 3600         # 1本1時間まで
```

## 9. 第2版：話題ごとの切り分け・3台同時処理（2026-10-28 オーナー決定）

参考：「加藤純一切り抜き集」（登録者61.5万人）。配信を話題・1試合ごとに切り分け、1日に何本も出す方式。

### 9.1 出すもの（1配信あたり）

| 種類 | 中身 | 本数 |
|---|---|---|
| 話題動画 | 1つの話題・1試合・1つの出来事を、途中で切らずにそのまま。5分〜1時間40分 | 配信の中身に応じて3〜8本 |
| 名場面まとめ | 話題にまとまらない細かい山場を、テンポよくつなぐ（従来の速報） | 0〜1本 |
| ショート | 一番の山場 | 1本 |

- 動画は面白さの順に YouTube へ上げ、1日の上限を超えた分は翌日以降に上げ直す（ドライブ保存は7日）。
- 公開の仕方は `youtube.privacy`（現在 public）。

### 9.2 処理の流れ（GitHub Actions を3つの段に分ける）

1. **計画（1台）**：チャット取得 → 1分ごとの「チャットの流れ」（件数・多かったコメント・ゲーム名）を作る → Claude①が話題の区切りと動画の案を出す → 区切りの前後と山場だけを文字起こし・静止画取得 → Claude②が開始・終了の微調整、タイトル、サムネの言葉、顔の位置、チャプター、概要欄を決める → `plan.json`
2. **書き出し（最大5台を同時に）**：動画1本につき1台。必要な区間だけをダウンロードし、流れるコメント付きで書き出し、サムネを作り、ドライブと YouTube に上げる
3. **仕上げ（1台）**：結果をまとめて `candidates.md`・`upload.md`・`metadata.json` をドライブに保存し、`state/processed.json` を更新、上げ直し待ちを処理する

- 文字起こしは「話題の区切りの前後」と「山場」だけにする（配信全体は文字起こししない）。
- 長い話題動画は 1080p・30fps・`crf 24`・`superfast`・最大3Mbps で書き出す（上限なしでは30分で約1.5GBになり、ドライブがあふれたため）。
- ドライブは上げ直し待ちの置き場とし、YouTube に上がった動画ファイルはドライブに置かない（サムネ・upload.md などは置く）。上げ直しで上がった動画も、その場でドライブから消す。
- 2026-10-30：単体動画は1配信4本までに減らす（1日2配信が多く、6本だと1日8本の枠を超えて大半が取りやめになったため）。
- 2026-10-29〜：ダイジェストを止め、単体動画（1配信6本まで）に集中する。ショートは据え置き（YouTube の説明では、ショートの視聴は長い動画のおすすめを押し上げないため）。数日後に Studio の「ブラウジング機能・関連動画」からの表示を見て判断する。
- 表示を増やすため（2026-10-29）：タイトルの前半に検索されそうな言葉を入れる（`prompts/finalize_topics.md`）、タグにゲーム名を足す、ゲームごとの再生リスト「〇〇｜加藤純一 切り抜き」（公開）に自動で入れる（OAuth の許可に `youtube` を追加）。
- サムネの瞬間は、Claude② が選んだ時刻の前後数秒（-6〜+4秒）の6枚から、Claude（Haiku）に表情の一番強い1枚を選ばせる（`prompts/pick_thumb_frame.md`）。文字は色付き・二重の縁・長ければ2段、切り抜いた顔に白い縁。
- 新しい配信がない見回り（6時間おき）では、上げ直し待ちを空いた枠で上げる（配信中は上げない）。
- `retry.yml` の起動は Cloudflare Worker の Cron Trigger（毎時47分）から repository_dispatch `retry_tick` で行う（GitHub の定期実行は飛ばされるため。GitHub 側の3時間おきは保険）。
- さらに `retry.yml` が1時間おきに、待ちと空き枠があり本処理が動いていないときだけ上げ直す（枠が空いてから1時間以内に上がるように。待ち・枠が無ければ数十秒で終わる）。
- 各ジョブは起動時点ではなく最新の main を取る（順番待ちの間に別の実行が処理済みの記録を足しているため。2026-10-29 に同じ配信を2回処理した）。
- ダイジェストは話題を1つずつ取得→書き出し→削除する（GitHub のサーバーの容量 約14GB を超えないため）。

### 9.3 タイトルの型（Claude②への指示に入れる）

- 「〇〇する加藤純一【YYYY/MM/DD】」、出来事を言い切る形（「鳥にタイマン挑んで現実を見る」）
- あだ名を使ってよい（「41歳」「サタン2人」）。先頭に【ゲーム名】や【ほぼ映画】【閲覧注意】などの煽りを付けてよい（誇張しすぎない）
- 最後は必ず【YYYY/MM/DD】
- 2026-10-31：タイトルが中身と合わない・日本語が変、という指摘を受けて次を足した。
  - Claude② に、区間の真ん中の山場（盛り上がり上位4つ）の文字起こしも渡す。
  - タイトルの中心にする言葉は、文字起こしか多くのチャットで確かめられるものに限る。
  - タイトルができたあと Claude③（`prompts/check_titles.md`）で点検し、意味が通らない・中身と合わないものを直す。
- 2026-10-31：Twitch が著作権の音楽などで音を消した区間（muted_segments）は動画に入れない。避けると3分未満しか残らない話題は作らない。ショートも無音区間にかかるものは出さない。

### 9.4 サムネの型（2026-11-03 見直し）

- 下に**1行の大きな言葉**（8〜12字）。色は赤か白、白フチの外にさらに太い黒フチの二重縁。画面の横幅いっぱいに大きく

- 加藤さんの顔を背景を消して切り抜き、**右側に大きく**（高さの7割ほど）。表情が強い瞬間を Claude② が選ぶ
- 左上にゲーム名を小さめに（黒い帯に白文字）。雑談は表示しない
- 背景はゲームの名場面やキャラが映っている瞬間を選ぶ。ロード画面・暗転・ロゴだけの画面は使わない
- ほかのチャンネルのデザインをそのまま真似しない（配色・配置の考え方だけ参考にする）
- 言葉は加藤さんのいちばん強いセリフをそのまま（文字起こしで確かめたもの）。無いときだけ出来事を一言で（2026-11-05 オーナー判断：再生の多い切り抜きは、セリフを大きく入れている）。
- 暗い画面・ぼやけた画面は使わない。顔はもっと大きく。
- 言葉の中の大事な一語（`thumb_emph`）だけを1.5倍ほど大きくし、前後は小さくする（2026-11-05 オーナー判断：一瞬で目に入る語を1つに絞る）。

### 9.5 手動のやり直しと足し算（2026-11-01 オーナー決定）

上がる前の動画の組み合わせを、オーナーの判断で変えるときの手段。自動の処理は変えない。

- **作り直し**：`gh workflow run run.yml -f vod_id=<VOD_ID> -f youtube=true` に、次の入力を足せる。計画からやり直すので、話題の区切りとタイトルも付け直しになる（Claudeを呼ぶ）。
  - `singles`：単体動画の本数
  - `shorts`：ショートの本数（0で作らない）
  - `prefer_game`：単体動画で優先するゲーム（例：BLEACH）
- **足し算**：`-f add=4,5 -f drop=shorts/short_01.mp4`。作った動画はそのままで、計画に残した話題（`plan.json` の `topics`）から足す分だけ書き出す。Claudeは呼ばない。
  - `drop` に書いた上げ直し待ちは取りやめる。ドライブからは消さない。
  - 足した動画は上げ直し待ちに入り、枠が空けば上がる。
  - 計画は全部の話題を `topics` に残し、ドライブの `metadata.json` に保存する（7日で消える）。足し算はそれを読む。

### 9.6 英語の会話の日本語字幕（2026-11-05 オーナー決定）

### 10.2 アップロードの順番と上げ直し

- 上げる順番：単体動画（`prefer` に当たる話題 → 面白い順）。上げ直し待ちも、`prefer` に当たる動画を持つ配信を先に、次に新しい配信から。今日の加藤純一・週間ランキングは決まった時刻に。

- 直近24時間の本数は、長い動画（`state/uploads.json`）とショート（`state/uploads_shorts.json`）を別に数える。
- 移行時、たまっている上げ直し待ちはダイジェスト（まとめ動画）3本だけ残し、ショート4本は取りやめる。

- ARC Raiders を遊んだ配信1本につき1本まで。5〜10分。
- 英単語・英語表現を5〜10個。1個につき、その単語が出た場面を20〜60秒切り抜き、続けて解説カードを出す。
- 解説カード：英単語、読み方（カタカナ）、意味、ゲームの中での使われ方、短い例文と訳。
- 題材は、加藤さんが口にした英語（アイテム名・敵の名前・読み間違いを含む）と、画面に大きく出た英語。読み間違いは笑いどころとして使ってよいが、正しい読みを必ず示す。
- タイトルの型：「【ARC Raiders】加藤純一と覚える英単語〇選｜〇〇の意味は？【YYYY/MM/DD】」。

### 11.2 作り方
- 材料：単体動画用にすでに取っている山場の文字起こしと静止画に、ARC Raiders の区間の静止画を数枚足す。
- Claude（`prompts/english_words.md`）が、材料から単語と場面（元配信の秒）を選び、解説カードの中身を書く。意味や読みは辞書的に正しいものだけにし、自信がない単語は選ばない。
- 書き出し：場面の切り抜き＋解説カード（ASS の字幕レイヤーで描く）をつなぐ。流れるコメントは場面の部分だけに付ける。

### 11.3 決まりの例外
- 方針「発言の字幕は付けない」の例外として、この動画だけ英語の解説カードを出す。加藤さんの発言そのものを字幕にはしない。
